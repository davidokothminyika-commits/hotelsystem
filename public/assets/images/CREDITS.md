# Image credits

Every image under `public/assets/images/` is committed to the repository, so the
site renders with no third party request and no broken image when the network is
unavailable. Two sources are used, and the licences differ.

## Restaurant menu: `dining/`

Fetched from **Wikimedia Commons** by `npm run images:menu`
(`scripts/fetch-menu-images.mjs`). Each file is licensed under Creative Commons
or is in the public domain.

The script only accepts a photograph when the Commons file title mentions the
dish it was searching for. Without that check, Commons returns a car for a
search of "martini" and a portrait of the inventor of nachos for a search of
"nachos", which is worse than no picture at all.

The machine readable record, including a link to each source file, is
`dining/manifest.json`. Re-running the script skips any file already on disk,
so the photography cannot silently change between runs.

The table above is generated from that manifest by
`scripts/fetch-menu-images.mjs`, between the `BEGIN GENERATED` and
`END GENERATED` markers. Edit the manifest, never the table by hand, or the
attribution silently drifts from the files that are actually shipped.

**Attribution requirement.** CC BY and CC BY-SA require credit to the author.
Keep this file with the code and reproduce it wherever the images are
redistributed. Cropped or resized derivatives, including the versions stored in
the `image` column and rendered by the card components, must carry the same
licence as the original.

## Replacing an image

These are placeholders for a demo dataset. To use a photograph of the real
property:

1. Drop the file into the matching folder and keep the filename, or update the
   path in `src/database/seed.js`.
2. Room type images are seeded into the `image` column of `room_types` and menu
   images into `menu_items`. Re-run `npm run seed` to apply.
3. Individual rooms and dishes can also be given an image from the admin
   screens, which writes the same column, so no code change is needed.
